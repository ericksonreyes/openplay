Conventions for authoring user guides and visual walkthroughs for OpenPlay channels.
STATUS: convention pinned (ADR-0009); implementation starts when the first frontend exists.

## Principle

**Screenshots and recordings are generated artifacts, never manual.** A guide references
`workspace/docs/screenshots/*.png` produced by Playwright scripts — regenerate on UI change rather
than letting visuals rot. If a screenshot can't be regenerated by a script, it doesn't
belong in the guide.

## Layout

```text
scripts/screenshots/<channel>/<flow>.spec.ts      — Playwright capture scripts
workspace/docs/screenshots/<channel>/<step>.png   — generated output (committed)
workspace/docs/guides/<channel>.MD                — per-channel user guide
```

## Capture conventions

- Scripts run against the running Docker stack — real app, real data (seeded
  demo fixtures, never production-like PII).
- One spec per documented flow (e.g. `player/book-court`, `venue/manage-schedule`,
  `platform/approve-business`, `public/browse-venue`).
- Capture states, not just happy paths: empty state, validation error, loading, success.
- Mobile viewport for player-facing flows (`devices['iPhone 13']` or equivalent) —
  the product is mobile-first.
- `recordVideo` for flow walkthroughs → `ffmpeg` to `.mp4`/`.gif` for README embedding.

## Guide conventions

- Per-channel markdown guide; embed the generated PNGs at each step.
- Numbered steps, one action per step, screenshot AFTER the action shows its result.
- Mark anything AI-generated in the UI explicitly — the AI boundary
  (ADR-0006) should be visible in guides too.
- Keep guides terse — the visuals carry the demo; text is caption, not essay.

## When adding a user-facing flow

1. Write/update the Playwright spec, regenerate screenshots.
2. Update the channel guide's steps and image references in the same change.
3. Verify every `![](...)` path resolves — same link rules as specs (AGENTS.md).
